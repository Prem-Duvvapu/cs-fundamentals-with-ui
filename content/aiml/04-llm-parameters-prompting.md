# LLM Sampling Parameters, Tokenization & ReAct Agent Architecture

## 🟢 Beginner Level

### Tokenization
LLMs do not process raw text strings; they process numerical **Token IDs** generated by a **Tokenizer** (e.g. Byte-Pair Encoding / BPE, Tiktoken).

```
Raw Text:  "Database Indexing"
Tokens:    ["Data", "base", " Index", "ing"]
Token IDs: [15492,   3102,     9481,   278]
```

### Core Sampling Parameters

1. **Temperature ($T$)**: Controls output randomness by scaling logits before Softmax normalization ($z_i = \text{logit}_i / T$).
   - $T = 0.0$: Deterministic (**Greedy Decoding**). Always selects the highest probability token. Best for SQL generation & math.
   - $T = 0.7 - 1.0$: Creative & diverse. Best for brainstorming & creative writing.
2. **Top-P (Nucleus Sampling)**: Selects tokens from the smallest cumulative probability set exceeding $P$ (e.g., $P = 0.9$).
3. **Top-K Sampling**: Limits token candidates to top $K$ highest probability tokens (e.g., $K = 40$).
4. **Presence & Frequency Penalties**: Penalizes tokens if they have already appeared in the generated text to eliminate repeating loops.

## 🟡 Intermediate Level

### LLM Agent Architecture & Function Calling

Modern backend systems turn LLMs into autonomous **Agents** that perform multi-step actions by calling internal REST APIs.

```
USER PROMPT: "Check account balance for User #101 and transfer $50 to User #202."
                               │
                               ▼
                   ┌───────────────────────┐
                   │    LLM Agent Loop     │
                   └───────────┬───────────┘
                               │
            ┌──────────────────┴──────────────────┐
            ▼                                     ▼
1. Function Call Output:               2. Execution Result:
   "get_balance(user_id=101)" ────────► Balance = $500
                                                  │
            ┌─────────────────────────────────────┘
            ▼
3. Next Function Call Output:          4. Final Response:
   "transfer(from=101, to=202, amt=50)"► "Transferred $50 successfully!"
```

## 🔴 Expert Level

### ReAct (Reasoning + Acting) Agent Framework

The **ReAct Pattern** structures LLM agent execution loops into three explicit phases: **Thought**, **Action**, and **Observation**.

```
Thought 1: I need to check the inventory level for Product SKU-88.
Action 1:  Call Tool: query_inventory(sku="SKU-88")
Observation 1: {"sku": "SKU-88", "stock": 42}
Thought 2: Inventory is 42 units. I can now create the order.
Action 2:  Call Tool: create_order(sku="SKU-88", qty=1)
Observation 2: {"order_id": "ORD-9912", "status": "SUCCESS"}
Thought 3: Order successfully created. I will reply to the user.
Final Answer: Order #ORD-9912 has been placed for SKU-88.
```

### Interview Questions

1. **How do Function Calling / Tool Calling JSON schemas prevent prompt injection vulnerabilities?**
   - *Answer*: System prompts define strict JSON Schema constraints (`type`, `properties`, `required`). The inference engine enforces structured output parsing (e.g., Guidance, Outlines, Jsonformer), rejecting non-conforming responses before executing backend actions.

2. **What is the difference between Temperature scaling and Top-P Nucleus sampling?**
   - *Answer*: Temperature rescales the continuous logit probability distribution across ALL vocabulary tokens, whereas Top-P truncates the tail of low-probability tokens dynamically based on cumulative mass cutoff.
