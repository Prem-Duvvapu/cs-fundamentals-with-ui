# Memory Management

## 🟢 Beginner Level

### What is Memory Management?
The OS manages the computer's main memory (RAM) — allocating it to processes, tracking usage, and deciding which process gets what memory.

### Logical vs Physical Address
- **Logical Address**: Generated by the CPU (virtual address)
- **Physical Address**: Actual location in RAM
- **MMU (Memory Management Unit)**: Hardware that maps logical → physical

### Contiguous Memory Allocation
Memory is divided into fixed or variable-sized partitions:

```
OS ────────────────
Process 1 ─────────
Process 2 ─────────
Free Space ────────
```

**Problems**: External fragmentation (small gaps between processes) and internal fragmentation (unused space within a partition)

### Swapping
A process can be swapped out to disk (to a swap partition) and brought back later — allows running more processes than physical RAM.

## 🟡 Intermediate Level

### Paging
Physical memory is divided into **frames** (fixed-size), logical memory into **pages** (same size).

Every process has a **page table** mapping page → frame.

```
┌──────┐    ┌──────┐
│Page 0│───→│Frame │
│Page 1│───→│Frame │
│Page 2│───→│Frame │
│Page 3│───→│Frame │
└──────┘    └──────┘
```

**Advantage**: No external fragmentation, can use any free frame.

**Disadvantage**: Internal fragmentation possible (last page), page table overhead.

### Page Table Structure
- **Page Number (p)**: Index into page table
- **Page Offset (d)**: Offset within the page
- **Page Table Entry (PTE)**: Contains frame number, valid bit, dirty bit, reference bit, protection bits

### Translation Lookaside Buffer (TLB)
A hardware cache for page table entries — avoids expensive memory accesses for page table lookups.

- **TLB Hit**: Translation done in 1 CPU cycle
- **TLB Miss**: Need to access page table in memory (2 memory accesses)
- **Effective Access Time**: `Hit_Ratio × TLB_Hit + (1 - Hit_Ratio) × TLB_Miss`

### Multi-level Page Tables
For 64-bit systems, a flat page table would be enormous. Multi-level tables save memory:

```
Page Table → Page Mid Dir → Page Global Dir → Physical Frame
```

### Segmentation
Memory is divided into logical segments (code, data, stack, heap):

```
Segment Base + Limit → Physical Address
```

Segmentation + Paging combined (x86 architecture): Segments are paged.

### Virtual Memory
Allows executing processes that aren't fully in memory:

- **Demand Paging**: Pages loaded only when needed (page fault)
- **Page Replacement**: When memory is full, evict a page
- **Thrashing**: Excessive paging — process spends more time paging than executing

### Page Replacement Algorithms

| Algorithm | Strategy | Issues |
|-----------|----------|--------|
| **FIFO** | Evict the oldest page | Belady's anomaly (more frames → more faults) |
| **OPT** | Evict page used farthest in future | Impossible (needs future knowledge) |
| **LRU** | Evict least recently used page | Hardware support expensive |
| **Clock (NRU)** | Circular scan, clear reference bit | Approximates LRU efficiently |

### Frame Allocation
- **Equal**: Give each process same number of frames
- **Proportional**: Allocate by process size
- **Global vs Local Replacement**: Global can steal from other processes

## 🔴 Expert Level

### Linux Page Table (x86-64)
4-level page table hierarchy:

```
PGD → P4D → PUD → PMD → PTE → Physical Page
```

- Page size: 4KB (standard) or 2MB/1GB (huge pages)
- Each level indexed by bits from virtual address
- TLB reach = TLB_entries × Page_Size

### Huge Pages
- 2MB (x86-64) or 1GB pages reduce TLB misses
- **Transparent Huge Pages (THP)**: Kernel automatically promotes 4K → 2M
- Critical for databases, VMs, and HPC applications

### Memory Overcommit & OOM Killer
- Linux overcommits memory: allows more allocated than physically available
- When actual memory runs out, **OOM Killer** selects a process to kill
- `oom_score` calculated from memory usage, runtime, etc.
- `oom_adj` can tune which process gets killed

### NUMA (Non-Uniform Memory Access)
- Each CPU socket has local memory (lower latency)
- Accessing remote memory (another socket) is slower
- Linux NUMA scheduler tries to keep processes on their home node
- `numactl` to control memory/CPU binding

### KSM (Kernel Same-page Merging)
- Merges identical pages from different processes (e.g., multiple VMs)
- Reduces memory footprint for similar workloads
- Used heavily in virtualization (KVM)

### Page Cache & Writeback
- Page cache caches file data in memory
- **Dirty pages**: Modified in cache, not yet written to disk
- **pdflush** / **writeback** threads flush dirty pages
- `dirty_ratio`, `dirty_background_ratio` tunables

### Slab Allocator
Linux uses slab allocator for kernel objects:
- Avoids fragmentation for fixed-size objects
- **Slab**: Contiguous memory containing same-sized objects
- **Cache**: Collection of slabs for one object type
- Objects are colored to avoid cache line conflicts
